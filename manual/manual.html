1. Introduction

PEJVAK RVB is a professional algorithmic reverb that combines two completely independent DSP engines in a single plugin. You can switch between them at any time from the header, and each engine has its own layout, character, and set of controls.

CloudSeed Engine

A faithful port of Valdemar Erlingsson's CloudSeed (legacy-v1) — 49 parameters, twelve parallel delay lines, deep early-diffusion front-end, and a warm, dense tail. Every arithmetic operation runs in f64 and is bit-identical to the original C++ DSP.

FFDN Engine

A modern Filtered Feedback Delay Network based on Fagerström (DAFx 2020) and Schlecht (IEEE TSP 2017). It reaches comparable echo density with a cleaner signal path, and exposes character controls — cross-feed, Velvet saturation, spectral tilt, three dynamics stages, and a Time-Varying Feedback Matrix — that the CloudSeed engine does not have.

On top of the two engines

  • Texture Rack — six post-reverb texture layers with click-free enable and reorder. Available on both engines.
  • ILLUSION — a granular cloud with pitched overtones and eight techniques that keep it click-free.
  • Velvet-Noise VFDN — a sparse diffusion stage inside the CloudSeed engine.
  • Undo / Redo — 50 steps with parameter-name tooltips.
  • Check for Updates — built-in updater with SHA-256 verified installer downloads.
  • 100 factory presets across 16 categories.

2. Installation

Download the installer for your platform from the GitHub Releases page. Every release ships a native installer that handles the platform-specific quirks (Mark-of-the-Web on Windows, Gatekeeper on macOS) automatically.

Windows

Download and run PEJVAK-RVB-windows-x64-setup.exe. The self-extracting installer:

  1. Removes the Windows security block (Mark of the Web) from the bundled plugin files.
  2. Creates the VST3 and CLAP system directories if they do not exist.
  3. Copies the VST3 bundle and the CLAP plugin into their respective folders:
    C:\Program Files\Common Files\VST3\Pejvak_RVB.vst3\ C:\Program Files\Common Files\CLAP\Pejvak_RVB.clap
  4. Pauses for confirmation once installation completes.
If Windows SmartScreen shows a warning about the installer, click More info → Run anyway. The installer is not yet Authenticode-signed; the SHA-256 verification in the built-in updater guarantees integrity even without code signing. The SmartScreen warning will disappear once the installer receives a code-signing certificate.

A portable ZIP (PEJVAK-RVB-windows-x64-portable.zip) is also published for users without administrator rights. Extract it and copy the two files manually — the bundled README.txt documents the exact paths.

macOS (Universal Binary)

Download and double-click PEJVAK-RVB-macos-universal.pkg. This is a standard Apple package installer that:

  1. Installs the VST3 and CLAP bundles into the system-wide plug-in folders:
    /Library/Audio/Plug-Ins/VST3/Pejvak_RVB.vst3 /Library/Audio/Plug-Ins/CLAP/Pejvak_RVB.clap
    The macOS installer prompts for administrator credentials.
  2. The bundles are ad-hoc codesigned after lipo and strip, so Apple Silicon and Intel Macs can both load them without a developer certificate.

The package is universal — it runs natively on both Apple Silicon (M1/M2/M3/M4) and Intel Macs. No Rosetta required.

Prefer a per-user install (in ~/Library/Audio/Plug-Ins/) or do not want to enter an admin password? Download PEJVAK-RVB-macos-universal-portable.zip instead and copy the two bundles manually — the included README.txt documents the exact paths and how to strip the Gatekeeper quarantine flag.
If macOS still blocks the plugin the first time you load it in your DAW after a manual ZIP install: System Settings → Privacy & Security → "Open Anyway". This is only necessary once. The PKG installer handles this automatically; the warning mainly concerns users of the portable ZIP.

Linux

Two packages are published:

  • PEJVAK-RVB-linux-x64.deb — for Debian / Ubuntu. Install with sudo dpkg -i.
  • PEJVAK-RVB-linux-x64.tar.gz — portable archive. Extract and copy the two bundles manually.

Manual install from the tarball:

# VST3 mkdir -p ~/.vst3/Pejvak_RVB.vst3/Contents/x86_64-linux cp "Pejvak_RVB.vst3/Contents/x86_64-linux/Pejvak_RVB.so" \ ~/.vst3/Pejvak_RVB.vst3/Contents/x86_64-linux/ # CLAP mkdir -p ~/.clap cp Pejvak_RVB.clap ~/.clap/

Then rescan plugins in your DAW (or restart it).

The Linux build is compiled against the current Ubuntu LTS toolchain. It requires the standard libx11, libxcb, libgl1, and libasound2 packages, which are almost always present on a desktop system.

Updating

Once installed, use the ☰ → Check for updates option inside the plugin. It will:

  1. Query the GitHub Releases API and compare the remote tag against the installed version.
  2. Show the release notes for any newer version.
  3. Download the appropriate installer for your platform (with SHA-256 verification).
  4. Offer a button to run the installer once you have closed your DAW.

See §4.5 for details.

2b. Building from Source

PEJVAK RVB is written in Rust. The build requires Rust 1.98 or newer. All plugin binaries are produced from a single workspace — no external C++ toolchain, no VST3 SDK download needed.

Prerequisites

Windows

rustup target add x86_64-pc-windows-msvc

macOS

Install Xcode Command Line Tools, then add the two macOS targets:

xcode-select --install rustup target add aarch64-apple-darwin rustup target add x86_64-apple-darwin

Linux

Install the graphics and windowing dependencies, then add the target:

sudo apt-get install -y \ libx11-dev libxcursor-dev libxcb-dri2-0-dev \ libxcb-icccm4-dev libx11-xcb-dev mesa-common-dev \ libgl1-mesa-dev libglu1-mesa-dev rustup target add x86_64-unknown-linux-gnu

Build

Windows / Linux

cargo build -p Pejvak_RVB --release cargo nice-plug bundle Pejvak_RVB --release

macOS — universal binary

Build both architectures separately, then combine them with lipo:

cargo build -p Pejvak_RVB --release --target aarch64-apple-darwin cargo build -p Pejvak_RVB --release --target x86_64-apple-darwin mkdir -p target/universal/release lipo -create \ target/aarch64-apple-darwin/release/libPejvak_RVB.dylib \ target/x86_64-apple-darwin/release/libPejvak_RVB.dylib \ -output target/universal/release/libPejvak_RVB.dylib cargo nice-plug bundle Pejvak_RVB --release

Run the test suite

# 42 DSP tests cargo test -p fdn_reverb_core # 12 plugin tests (XML parser, parameter handling, updater, string parsing) cargo test -p Pejvak_RVB # 54 tests total
The DSP core (fdn_reverb_core) has no OS-specific code, so its tests run identically on all three platforms. If you are contributing DSP changes, they can be validated without a graphical environment.

Run clippy

cargo clippy --workspace --all-targets -- -D warnings
--all-targets is essential: without it, test code is silently skipped by clippy. The CI pipeline runs this exact command, so a PR that introduces a lint will fail the build before it can be merged.

3. Quick Start

  1. Insert PEJVAK RVB on a track in your DAW.
  2. Click the preset name in the header to open the preset browser. Try Small Wood Room for a start.
  3. Drag the Dry and Late faders in the MIXER card to balance the dry signal against the reverb tail.
  4. Use the Size and Decay knobs in SPACE (FFDN) or LATE DELAY (CloudSeed) to shape the space.
  5. If you want more character, enable a Texture layer from the TEXTURE tab and pull its Mix knob up.
The fastest way to hear the difference between the two engines is to load the same preset category once on CLOUD and once on FFDN. The Halls category exists in both and gives a very direct comparison.

4. Interface Overview

The interface is divided into a persistent header and two switchable pages: MAIN (the currently selected reverb engine) and TEXTURE (the Texture Rack and ILLUSION).

┌─────────────────────────────────────────────────────────────────────────────┐ │ PEJVAK RVB [MAIN|TEXTURE] [TX] [CLOUD|FFDN] [Bypass|Freeze|Interp] │ │ [↶|↷] [Preset▾] [☰] [☀] │ ├─────────────────────────────────────────────────────────────────────────────┤ │ │ │ (page content — MAIN or TEXTURE) │ │ │ └─────────────────────────────────────────────────────────────────────────────┘

4.1 Header

ControlFunction
MAIN | TEXTURESwitch between the reverb engine page and the Texture Rack page.
TXKill switch — locks all seven Texture layers off in one click. See §9.
CLOUD | FFDNSelects the active reverb engine. Switching clears the departing engine's buffers so no stale tail bleeds through.
BypassHost-integrated bypass — the plugin passes audio through untouched. The button gently breathes at 1.5 Hz while bypass is engaged, so you can tell at a glance that you are hearing the dry signal.
FreezeHolds the current reverb tail indefinitely. New input is rejected; existing sound keeps circulating.
InterpEnables delay-line interpolation (smoother modulation at a small CPU cost). CloudSeed only.
↶ ↷Undo / Redo. Hover shows which parameters the next action will affect. See §4.4.
Preset ▾Opens the preset browser. The ◀ ▶ arrows step through presets without opening the list.
☰Plugin menu — Manual, Size, Check for updates, Show pop-ups, About. See §4.2.
☾ / ☀Toggles the plugin theme between dark and light.
Keyboard forwarding. When the plugin window has focus, the standard DAW shortcuts — Space (Play/Stop), Enter, Esc, Tab, Backspace, Home, End, the arrow keys, the ten Numpad number keys, and the Numpad operators + - * / . , — are forwarded to the host as if you had pressed them in the DAW itself. This works in Reaper, Sonar/Cakewalk, Cubase, Studio One, Bitwig, and Ableton. A short "loop-prevention" guard ignores the host's echo of the same key for 50 ms so Reaper does not get stuck in a Play/Stop flicker when Space is pressed. While a parameter text field is being edited, forwarding is disabled so you can type freely.

4.2 Menu ☰

Five items, listed top to bottom:

  • Manual — opens this document in your browser.
  • Size — a hover flyout listing UI-scale presets from 70 % to 300 % (70, 80, 90, 100, 110, 120, 130, 150, 170, 200, 250, 300). The bottom of the list has Set as default size, which saves the current window dimensions to a small window_size.cfg file in the plugin's user folder. That file is read on startup, so the plugin always opens with your preferred size across every DAW and every project, without needing to save the host project first.
  • Check for updates — queries GitHub for a newer release. See §4.5.
  • Show pop-ups — toggles all hover tooltips on and off. Useful for screen recordings where tooltip flicker is distracting. The setting is remembered across sessions. Clicking this item closes the menu immediately.
  • About — version information and build details.

4.3 Preset Browser

Click the preset name in the header to open the browser. It groups 100 factory presets into 16 colour-coded categories and provides:

  • Search box — filters the visible list as you type.
  • Init — loads the factory default state.
  • Save Preset… — writes the current state to a user XML file in %APPDATA%\PEJVAK RVB\Presets\ (Windows) or ~/.config/PEJVAK RVB/Presets/ (macOS / Linux). The window_size.cfg file lives in the same directory.
  • Load Preset… — reads a user XML preset from disk.
  • User Presets — a section listing every .xml file you have saved.
Loading a preset from an older version is safe: the XML format is append-only, and any parameter that the file did not carry keeps its current value.

4.4 Undo / Redo

The history covers every user-visible parameter, plus the active engine, the current page, and the preset name. Up to 50 steps are retained.

  • One drag = one undo step. Dragging a knob from 0 to 100 creates a single history entry, not a hundred.
  • Engine and page switches do not create entries on their own. But if you change a parameter on FFDN and press Undo, you are returned to FFDN automatically.
  • Tooltips tell you what will change. Hover over ↶ or ↷ to see a summary such as Undo: Size, Decay.
  • Undo never cuts the reverb tail. A parameter jump is smoothed in the DSP over ~10 ms rather than by resetting the reverb buffers.

4.5 Check for Updates

Select ☰ → Check for updates to open the updater. It performs four steps:

  1. Check — queries https://api.github.com/repos/Pejvak-DSP/PejvakRVB/releases/latest, compares the tag against the installed version, and shows the release notes for any newer version.
  2. Download — pulls the installer for the current platform:
    Windows: PEJVAK-RVB-windows-x64-setup.exe macOS: PEJVAK-RVB-macos-universal.pkg Linux: PEJVAK-RVB-linux-x64.deb (or .tar.gz on non-Debian)
  3. Verify — computes the SHA-256 of the downloaded file as it streams, then compares it against the immutable digest published by GitHub. A mismatch deletes the partial file and refuses the install. A release that does not carry a digest is also rejected.
  4. Install — shows a Open Installer button. You must tick an explicit confirmation checkbox before the plugin will run a downloaded binary.
Close your DAW before running the installer. The plugin file is locked while the DAW has it loaded, so the installer cannot replace it until the host has released the file handle.
The updater is designed to be safe by default:
  • HTTPS-only requests — a malicious mirror cannot downgrade the connection to plaintext.
  • SHA-256 verification against GitHub's immutable digest.
  • Explicit confirmation before launching the installer.

4.6 Plugin Disabled Overlay

When your DAW takes the plugin offline (in Ableton this is Deactivate, in Bitwig Suspend, in Reaper Offline — the exact name varies), the plugin's UI dims and displays a full-window overlay with the message:

PLUGIN DISABLED Enable the plugin in your DAW to resume editing.

The overlay blocks every click, so you cannot accidentally edit a parameter that would not be heard. It disappears as soon as the host reactivates the plugin.

This overlay is not the same as the internal Bypass button. Bypass is a plugin parameter that passes audio through; Deactivate is a host operation that stops the plugin from processing entirely. The overlay only appears for the latter.

5. CloudSeed Engine

The CloudSeed page shows nine cards in a three-column grid. Every card has a title and, when relevant, an enable switch on the right.

An allpass diffuser inside every delay line's feedback loop. This is what gives CloudSeed its characteristic dense, breathing tail. Controls are identical to EARLY DIFFUSION.

6.5 MODULATION ★

Two rows of knobs. The first row shapes the master high-frequency damping and the delay-line modulation; the second row controls the Time-Varying Feedback Matrix.

ControlRangeDescription
Damping500 – 20 000 HzOne-pole low-pass inside every delay line. This is the primary HF shaper — use it before reaching for Loop LP.
Mod Amt0 – 3 msLFO depth on each delay line. 0 = static tail.
Mod Rate0.1 – 5 HzLFO speed for the per-line delay modulation.

6.5b TIME-VARYING MATRIX

A second pair of knobs under the MODULATION card:

ControlRangeDescription
Matrix Amt0 – 100 %Depth of the time-varying Givens rotation applied to pairs of delay lines. At 0 % the matrix is fully static and the engine is bit-identical to the previous release. As the value rises, the feedback matrix rotates further on every LFO cycle, producing a lush, evolving, decorrelated tail without any of the metallic ringing that a static matrix exhibits.
Matrix Rate0.01 – 2.0 HzSpeed of the Givens rotation. The rotation is driven by a continuous sine wave, not a sawtooth. This is important: a sawtooth would introduce a phase jump every cycle, and the resulting discontinuity would be audible as a click at high modulation depths. The sine-driven approach is what makes the modulation usable at 100 % Amt without artifacts.
The Time-Varying Matrix rotates in-place with a pre-computed sin/cos pair, so it costs only a handful of multiplies per sample per pair of delay lines. It has no effect when Matrix Amt is exactly 0 % — at that point the code path is skipped entirely.
A subtle Matrix Amt of 10–20 % with a slow Matrix Rate of 0.05–0.15 Hz is the sweet spot for long, evolving halls. Higher values (50 %+) produce a distinctly "alive" tail — useful for ambient textures and for breaking up metallic resonances on dense source material.

6.6 FILTER ★

ControlRangeDescription
Loop HP20 – 500 HzHigh-pass inside the feedback loop. At 20 Hz it is bypassed (neutral).
Loop LP2 – 20 kHzSharper (12 dB/oct) low-pass inside the loop, stacked on top of Damping. At 20 kHz it is bypassed.
Mid Focus0 – 100 %Cuts both ends at once — up to −6 dB below 400 Hz and −6 dB above 1500 Hz — focusing the tail on the mid band. Never boosts, so the loop stays unconditionally stable.

6.7 DYNAMICS ★

Three post-network gain stages. All live after the FDN, so they cannot destabilise the feedback loop.

ControlRangeDescription
Attack0 – 100 %Softens the initial transient of the wet signal. 0 % = instant; up to 500 ms swell at 100 %.
Ducking0 – 100 %Reduces the wet while dry input is present, recovers in silence. Classic vocal reverb behaviour. Up to −24 dB of attenuation at full amount.
Gate0 – 100 %Progressively silences the wet once its envelope drops below a threshold. Threshold range −60 dBFS to −10 dBFS, with a squared fade for a decisive close.
The FFDN INPUT card shows three knobs (Pre-Dly, Low Cut, High Cut). The Blend knob is not present because the FFDN already has the Cross control in CHARACTER, which covers the same range more cleanly.

7. Texture Rack

Six post-reverb layers that run in series on the wet signal. The rack is available on both engines — CloudSeed and FFDN — so you can stack the same textures on either reverb character. Each layer has its own Mix knob and its own enable switch in the card title. At Mix = 0 a layer is bypassed entirely — the rack is bit-identical to a plain reverb.

Every layer implements the same anti-click scheme: a 20 ms one-pole smoother on the Mix parameter, and a runtime-state reset on the rising edge from exactly zero. This means toggling a layer's enable switch or dragging its Mix knob from zero produces no click.

7.1 SIGNAL CHAIN

The bottom of the TEXTURE page shows the six layers as a row of chips. Their left-to-right order is the actual processing order.

  • Drag a chip — as soon as the pointer crosses the midpoint between two slots, they swap. The chips slide smoothly between positions.
  • Click an arrow — swaps the two adjacent layers.
  • Grey chips represent layers that are currently disabled. They still participate in the chain order but do not process audio.
Placing SHIMMER last produces a smooth, top-down wash. Placing it first adds the pitched content before the rest of the textures diffuse it — useful for a more aggressive shimmer.

7.2 SHIMMER

A classic Eno/Lanois shimmer: a granular pitch-shifter inside a feedback loop, with high-cut and low-cut shaping the tone.

ControlRangeDescription
Pitch−12 – +12 st0.5 = unison; below = down-shift; above = up-shift.
Feedback0 – 95 %How much of the shifted signal is fed back. Above 85 % the tail becomes quite long.
LowCut20 – 2000 HzHigh-pass before the shifter.
HighCut200 – 15 200 HzLow-pass after the shifter.
Mix0 – 100 %Amount of shimmer in the output.

7.3 MIST

A soft, hazy thickening: short modulated delay with light feedback, band-limited by an HPF and an LPF.

ControlRangeDescription

7.4 DRIFT

A very slow pitch wobble — a tiny (< 0.4 ms) modulation on a short delay line. Makes the reverb feel alive without being audible as vibrato.

ControlRangeDescription

8. ILLUSION — Granular Cloud

A granular cloud with pitched overtones and a musical envelope follower. ILLUSION is not a Texture layer — it runs after the Texture Rack, on the full wet signal. It can be enabled or disabled from its own card at the bottom of the TEXTURE page.

ControlRangeDescription
Spark0 – 100 %Granular cloud amount. 0 % = bypass. On the rising edge from exactly 0 the cloud fades in over one second, so a very small Spark value never "snaps on" as a distinctive texture.
Still0 – 100 %Motion smoothness. 0 % = scattered; 100 % = calm, meditative.
Aura−24 – +24 stPitch shift. At 0 st the internal sequence plays. Any non-zero value overrides the sequence with a fixed transposition.
Veil0 – 85 %Feedback into the capture buffer. Higher = repeating patterns, hazy wash.
Wide0 – 200 %Stereo width of the wet signal.
Tint800 – 18 000 HzTone of the wet signal.
Rate0.5 – 10 HzClock speed. 0.5 Hz = very slow; 10 Hz = fast arpeggio.
Grain30 – 300 msLength of each grain. Longer = smoother and more legato.

Anti-click design

Granular engines click easily. ILLUSION uses eight independent techniques to avoid it: grain length capping by pitch ratio, safety margins on grain start positions, smoothstep fade-in and fade-out on every grain, Catmull-Rom cubic interpolation, a DC blocker on the grain sum, soft-clip on the feedback path, output smoothing at 10 kHz, and denormal flushing. The result is a cloud that stays click-free even when you sweep the knobs quickly.

9. TX Kill Switch

The TX button in the header is a master switch for all seven Texture Rack layers plus ILLUSION.

  • Click once — remembers the enable-state of every layer, then turns them all off. The button pulses red to signal that the lock is active.
  • Click again — restores the exact enable-state that was captured.
  • The TX button is always togglable, even when every layer is already off. This lets you use it as a "lock" that blocks further changes to the layer switches from being pushed through by an accidental click or by host automation.
  • While the lock is active, the individual per-card enable switches are disabled. They show a soft red tone and their tooltip explains how to release the lock.
  • Undo and redo both cooperate with the TX lock: undoing past the moment it was engaged automatically unlocks it.

11. Automation

Every parameter — including the Texture Rack, ILLUSION, the FFDN engine, and the new Time-Varying Matrix controls — is exposed to the host for automation. Parameter IDs follow the CloudSeed XML naming scheme so presets port cleanly between the plugin and the original CloudSeed.

Parameter names

Every parameter is exposed under a stable DAW-visible name. Two entries use descriptive names that reflect what the control actually does:

XML nameDAW-visible nameControls
FfdnDriveSaturationAmount of Velvet saturation applied inside the FFDN feedback loop.
FfdnDriveEnabledSaturationEnabledEnable switch for the saturation stage.

Smoothing

All output-stage gains are smoothed inside the DSP with a 10 ms one-pole time constant. This means:

  • Automating a fader in the DAW never produces zipper noise.
  • Dragging a fader by hand produces a smooth amplitude ramp, not a staircase.
  • Preset loads still take effect instantly (the smoothing stage snaps on the first sample).

12. Troubleshooting

No sound / plugin not passing audio

  • Check that the Bypass switch in the header is off (if it is pulsing, bypass is engaged).
  • Check that the Dry fader in MIXER is not at −inf.
  • Check that the input is not being rejected by an aggressive Low Cut or High Cut.
  • If you see a PLUGIN DISABLED overlay, the DAW has taken the plugin offline — reactivate it in the host.

DAW shortcuts do not work while the plugin window is focused

  • This is intentional for some keys: while a parameter text field is being edited, forwarding is disabled so you can type freely. Press Enter or Esc to exit the text field and forwarding resumes.
  • If Space is not reaching the DAW at all, check that the host's own "allow plugin windows to steal keyboard focus" preference (if it has one) is enabled.
  • Some DAWs on Wayland forward keys to the OS compositor before the plugin window; try launching the host with GDK_BACKEND=x11.

Reverb tail is too short

  • Increase Decay (FFDN) or Decay in LATE DELAY (CloudSeed).
  • Check the SHELVES card: a Bass multiplier well below 1.0× and a Treble multiplier well below 1.0× will shorten the tail at both ends.
  • On CloudSeed, make sure Late Delay is enabled.

Clicks when toggling a Texture layer

This should not happen — all six layers implement anti-click. If you hear one:

  • Check that the Mix knob is not being automated to jump between 0 and a high value instantaneously. Use a short ramp in the host.
  • Make sure no other plugin in the signal chain is producing the click.

Clicks when using the Time-Varying Matrix

The matrix is driven by a continuous sine wave, so it should never click. If it does:

  • Check that Matrix Rate is not being automated with a stepwise envelope.
  • Reduce Matrix Amt below 20 % — at very high amounts the LFO phase can cross zero between host automation steps and produce a faint zipper.

Plugin crashes or hangs in the DAW

  • The DSP runs inside a catch-unwind guard, so a panic cannot crash the host — but it can silence the output for one block. If you see intermittent silences, please report a bug with your host and OS version.
  • Make sure your host's plugin sandbox is enabled. If the plugin misbehaves, a sandboxed instance can be killed without taking the host down.

Check for Updates fails

  • "No internet connection" — the updater needs to reach api.github.com. Check your firewall or proxy settings.
  • "No installer found for this platform" — this release does not ship an asset matching your OS. Use the Open Releases Page fallback and install manually.
  • "SHA-256 mismatch" — the download was corrupted or tampered with. Try again. If it fails repeatedly, download from the GitHub Releases page directly.
  • "No SHA-256 digest available" — the release predates GitHub's digest field. This is a rare case; install manually.

macOS: "Plugin cannot be opened because the developer cannot be verified"

This is standard Gatekeeper behaviour for unsigned binaries. The PKG installer already handles the quarantine attribute, but if your DAW still blocks the plugin after a manual ZIP install:

  • Open System Settings → Privacy & Security.
  • Scroll down to the security section. You should see a message about PEJVAK RVB being blocked.
  • Click Open Anyway and confirm.
  • Restart your DAW. The plugin will load normally from then on.

macOS: plugin does not appear in the DAW after installation

  • Confirm the PKG installed the plugin to /Library/Audio/Plug-Ins/VST3/ (system) or ~/Library/Audio/Plug-Ins/VST3/ (user, after a manual ZIP install).
  • Some DAWs (Ableton, Reaper, Bitwig) require you to add the folder to their plugin search path manually.
  • Rescan plugins from the DAW's preferences. On Logic Pro, use Logic Pro → Settings → Plug-in Manager and click Reset & Rescan Selection.

Linux: plugin fails to load with "libGL" or "libX11" errors

Some minimal Linux distributions do not ship the windowing libraries by default. Install them:

sudo apt-get install -y libx11-6 libxcursor1 libgl1 libglu1-mesa

On Fedora / RHEL-based distributions, use dnf with the equivalent package names.

Linux: Wayland vs. X11

The plugin runs under both Wayland and X11. If your DAW uses Wayland and you see rendering glitches, try launching the DAW with XWayland:

GDK_BACKEND=x11 your-daw

Text is too small / too large

Open the ☰ menu, pick Size, and choose a preset from 70 % to 300 % (the range now includes 250 % and 300 % for high-DPI displays). You can also drag the bottom-right corner of the plugin window to resize it freely; the aspect ratio is locked to 1100:570 so the layout never breaks. Use Set as default size at the bottom of the Size submenu to save your preferred dimensions for all future instances.

Tooltips get in the way

Open the ☰ menu and toggle Show pop-ups off. All hover tooltips will be suppressed until you toggle it back on.

Window opens at the wrong size

If you have resized the plugin and want it to remember that size globally (across every DAW and every project), open ☰ → Size → Set as default size. This writes a small window_size.cfg file to the plugin's user folder. The plugin reads it on startup and opens at exactly that size, without needing to save the host project first.

Windows SmartScreen warns about the installer

Click More info → Run anyway. The installer is not yet Authenticode-signed, so SmartScreen shows a warning the first time you run it. This is expected; the SHA-256 verification in the built-in updater guarantees integrity even without code signing.
